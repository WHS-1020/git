# 轧机监控平台（工业自动化监控平台 V1）

监控多台轧机设备的 PLC 数据：PLC 管理、设备管理、测点管理、实时数据采集、实时展示、报警管理、历史趋势、配置导入导出。

## 一、技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | ASP.NET Core 8 Web API |
| 数据库 | SQLite（Entity Framework Core 迁移） |
| 实时推送 | SignalR |
| 后台采集 | BackgroundService（每 2 秒一个周期） |
| PLC 协议 | S7（S7netplus 实现）/ Simulator（模拟采集器，明确标记为模拟数据） |
| 前端 | 原生 HTML + CSS + JavaScript（深色工业风格）+ ECharts 趋势图 |

## 二、运行环境要求

- Windows 10/11
- .NET SDK 8.0（已安装：`C:\Program Files\dotnet` 下有 8.0.425）
- 无需数据库安装（SQLite 单文件）

## 三、如何运行

### 方式 1：双击启动脚本（推荐）

1. 进入项目文件夹 `RollingMillMonitor`
2. 双击 **`启动服务.bat`**
3. 浏览器打开：**http://localhost:5200**

### 方式 2：命令行

```bat
cd RollingMillMonitor
dotnet run
```

首次启动会自动完成：数据库迁移（EF Core）→ 初始化数据 → 启动后台采集服务。

- 总览页：http://localhost:5200/index.html
- API 文档（Swagger）：http://localhost:5200/swagger
- 数据库文件：`RollingMillMonitor\Data\rollermill.db`（删除后重启会重新建库并初始化）

## 四、初始化数据（真实情况说明）

| 数据 | 说明 |
| --- | --- |
| 主PLC | **协议 = Simulator（模拟采集器）**。未提供真实 PLC 协议/地址表前的可替换方案，所有数据**明确标记为"模拟"**，不伪装成真实 PLC。 |
| 1#轧机（ROLLING-01） | 绑定主PLC，测点：温度 SIM-001（Real）、电流 SIM-002（Real）、油流 SIM-003（Bool 开关量状态）、油压 SIM-004（Bool 开关量状态）。油流/油压为状态测点：1=正常、0=故障，启用"故障报警"（报警延时 2s、恢复延时 3s），无需数值阈值。 |
| 2#轧机（ROLLING-02） | 测点已创建但**未绑定 PLC、地址为空**，页面明确显示"未配置：缺少 PLC 地址"，用于演示未配置状态。 |

> ⚠️ **本程序不虚构任何真实 PLC 地址**。现场接入时：
> 1. 在 PLC 管理中把"主PLC"协议改为 **S7**，填写真实 IP（端口 102、机架 0、槽号 1）；
> 2. 在测点管理中把各测点地址改为现场真实地址（如 `DB1.DBD0`、`DB1.DBD4`…）；
> 3. 保存后采集服务会自动按新配置连接和采集，页面不再显示"模拟"标记。
>
> S7 驱动当前支持的地址格式：`DB1.DBD0`（4字节）、`DB1.DBW0`（2字节）、`DB1.DBX0.0`（位）、`MW10`/`MD20`、`M0.0`、`IW10`/`ID20`/`QW10`/`QD20`。**读取时按测点配置的数据类型显式解析字节**（S7 为大端，解析时反转字节序），不使用 S7netplus 的字符串 `Read()`（它无法识别数据类型，会把 `DBD` 默认按 DWord 解析，导致 Real 浮点读成十亿级整数）。Modbus TCP / Modbus RTU 为预留协议，选择后会有明确"驱动未实现"提示，不会静默伪装。

## 五、系统状态判定（关键设计）

测点/设备状态由**配置**与**通信结果**共同决定，"没有实时值 ≠ 未配置"：

| 状态 | 判定条件 |
| --- | --- |
| 未配置 | 缺少绑定的 PLC 或缺少 PLC 地址 |
| 配置错误 | 地址解析失败、地址与数据类型不匹配、协议驱动未实现 |
| 通信故障 | PLC 无法连接 |
| 读取失败 | PLC 已连接但读取失败 / 采集异常 |
| 正常 | 成功读取到数据（应用倍率：最终值 = 原始值 × Scale + Offset） |
| 已禁用 | 设备 / 测点 / PLC 被禁用 |
| 未采集 | 已配置完整，等待首次采集（界面附加状态） |

每个状态都带**具体原因**展示（如"PLC 连接失败：…"、"地址 DB1.DBD4 与数据类型 Bool 不匹配"）。

## 六、页面功能一览

| 页面 | 功能 |
| --- | --- |
| 总览 | 统计卡片（设备/测点/正常/未配置/配置错误/通信故障/当前报警）、PLC 通信状态、设备卡片（实时值+状态+原因）、当前报警；SignalR 每 2 秒实时刷新 |
| PLC 管理 | 新增/编辑/删除/测试连接/启用禁用；显示连接状态、最后连接时间、最后错误 |
| 设备管理 | 新增/编辑/删除/复制配置/启用禁用；显示测点数量与综合状态；**复制配置不复制 PLC 地址**（新设备测点显示"未配置"） |
| 测点管理 | 新增/编辑/删除/启用禁用/立即读取；表格显示设备、PLC、地址、类型、单位、当前值、状态、原因、最后更新时间；表单含倍率/偏移/报警阈值/延时/死区 |
| 报警管理 | 高高/高/低/低低/通信报警；产生/恢复/确认/取消确认；按设备/类型/时间范围/确认/恢复状态筛选；显示持续时间 |
| 趋势 | ECharts 多测点对比、缩放（dataZoom）、1小时/8小时/24小时/7天范围、数据明细表、导出 CSV |
| 导入导出 | 导出 JSON / CSV（PLC+设备+测点+报警阈值）；导入整体校验（设备重名、PLC 不存在、地址格式、类型支持、测点重复），失败返回**具体行号与原因**，有错则整体不保存 |

## 七、API 一览

统一返回格式：成功 `{ success: true, data }`；失败 `{ success: false, message, field }`（失败还会带具体原因）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | /api/plcs | PLC 列表 / 新增 |
| PUT/DELETE | /api/plcs/{id} | 编辑 / 删除（其下测点解除绑定显示未配置） |
| POST | /api/plcs/{id}/test | 测试连接 |
| GET/POST | /api/devices | 设备列表 / 新增 |
| PUT/DELETE | /api/devices/{id} | 编辑 / 删除（级联删除测点/报警/历史） |
| POST | /api/devices/{id}/copy | 复制设备配置（不复制 PLC 地址） |
| GET/POST | /api/points | 测点列表（含实时值/状态）/ 新增 |
| PUT/DELETE | /api/points/{id} | 编辑 / 删除 |
| POST | /api/points/{id}/read | 立即读取 |
| GET | /api/overview | 总览快照 |
| GET | /api/alarms | 报警列表（多条件筛选） |
| POST | /api/alarms/{id}/ack、/unack | 确认 / 取消确认 |
| GET | /api/trends、/api/trends/export | 趋势查询 / 导出 CSV |
| GET | /api/config/export?format=json\|csv | 导出配置 |
| POST | /api/config/import | 导入配置（body: { format, content }） |

后端校验（新增/编辑测点时强制）：请选择所属设备 / 所属设备不存在 / 请选择绑定的 PLC / 绑定的 PLC 不存在 / 请输入 PLC 地址 / PLC 地址格式错误 / 地址与数据类型不匹配 / 不支持的数据类型 / 报警阈值合法性 / 同设备测点重名。**不保存半配置数据。**

## 八、完整测试步骤（对照验收标准）

> 前置：双击 `启动服务.bat`，浏览器打开 http://localhost:5200。默认情况下 1#轧机为模拟正常数据、2#轧机为未配置状态。

1. **新增 PLC**：PLC 管理 → 新增 PLC → 协议 S7、IP 192.168.1.200（任意）、端口 102 → 保存 → 列表出现。
2. **测试 PLC 连接**：点击"测试连接"→ 因 IP 不可达应显示"通信故障/连接失败"与错误原因（S7 驱动真实尝试连接；模拟采集器协议则立即成功）。把协议改回 Simulator 后测试应成功。
3. **新增设备**：设备管理 → 新增"3#轧机"（编码 ROLLING-03）→ 保存成功；名称重复会提示"设备名称已存在"。
4. **新增测点并验证校验**：测点管理 → 新增测点 → 设备选 3#轧机、PLC 选主PLC → 故意留空地址 → 保存 → 提示"请输入 PLC 地址"；填 `DB1.DBD0`、类型选 **Bool** → 保存 → 提示"地址 DB1.DBD0 不支持 Bool 类型"；填 `ABC` → 提示"PLC 地址格式错误"；不选 PLC → 提示"请选择绑定的 PLC"。以上全部拦截，证明后端校验生效。
5. **配置合法测点**：类型选 Real、地址 `DB1.DBD0` → 保存成功。此时因主PLC是模拟器且地址 SIM-001 才有数据，该测点若绑定模拟 PLC 但填了 DB 地址会按模拟器规则正常返回（模拟地址任意非空即可）。若要演示真实"读取失败"可用步骤 2 的 S7 PLC 绑定测点。
6. **总览状态区分**：总览页应同时看到：1#轧机测点全部"正常"（带"模拟"标记、有实时值）、2#轧机全部"未配置：缺少 PLC 地址"、3#轧机测点状态按实际配置显示。统计卡片数字与明细一致。
7. **油流/油压状态**：油流/油压为 **Bool 开关量状态测点**（1=正常、0=故障），总览/测点管理显示"**正常**"（绿色）或"**故障**"（红色），**不再显示 L/min / MPa 数值**，每 2 秒刷新。
8. **报警测试（油流/油压故障报警）**：模拟器 SIM-003/SIM-004 每 150 秒出现 8 秒"故障"（值=0）。等待故障窗口（或新建一个 Bool 测试测点绑 SIM-003）→ 报警延时 2 秒后报警管理出现"**故障报警**"（级别严重），内容为"油流故障：当前状态 0（1=正常，0=故障）"，总览该测点显示红色"故障"；窗口结束 + 恢复延时 3 秒后自动恢复"正常"。Bool 测点启用报警**无需数值阈值**，只有报警延时/恢复延时。报警确认/取消确认可正常操作。
9. **通信故障与恢复**：PLC 管理新增 S7 PLC（不可达 IP）→ 在其下新增测点并绑定 → 总览显示该设备"通信故障"，原因"PLC 连接失败：…"；把该 PLC 协议改为 Simulator → 下个周期自动恢复"正常"（模拟器连接必成功）。**状态自动恢复。**
10. **历史趋势**：趋势页勾选测点（温度/电流/油流/油压）→ 最近 1 小时（数据已积累）→ 折线图显示曲线，可缩放；数据明细表可见；"导出 CSV"下载文件用 Excel 可打开（Bool 测点趋势为 0/1 状态曲线）。
11. **导入导出**：配置页"导出 JSON"保存文件 → 改其中设备名后"导入"应报"设备名称已存在：…"且整体不保存；新建一个设备条目导入成功。导出 CSV → Excel 编辑（如新增 PLC 行）→ 导入成功。错误时显示具体行号与原因。
12. **删除测点**：删除 3#轧机某个测试测点 → 该测点相关报警与历史数据被级联清理，报警/趋势页不再出现。
13. **刷新不丢配置**：刷新任意页面 → 配置、报警、历史数据仍在（SQLite 持久化）。

## 九、日志与监控

**验收中发现并已修复的 6 个问题**：
1. 设备复制保存时外键约束失败（先保存设备再复制测点）；
2. 配置导入保存时外键约束失败（测点改用导航属性让 EF 回填外键）；
3. 趋势/报警页面查询时间用 UTC（带 Z），与本地存储时间错位导致 0 条数据 → 前端统一改为本地时间字符串（`toLocalIso`）。注意：`/api/trends` 与 `/api/alarms` 的 from/to 参数请使用**本地时间**（不带 Z）。
4. **S7 驱动 Real 字节序错误（现场真实 PLC 数值异常）**：S7netplus 字符串 `Read("DB58.DBD0")` 无法识别数据类型，把 `DBD` 默认按 DWord 解析，Real 浮点被读成超大整数（如温度 1107663258）。已改为 `ReadBytes` 读原始字节 + 按测点类型手动解析（S7 大端 → 反转字节 → BitConverter），温度恢复 33.8℃、电流 5.27A。Bool/Int/DInt/UInt/Real/Float/Word/DWord 全部按此规则解析。
5. **页面不实时（SignalR 连不上）**：后端未配置 CORS，局域网 IP / 127.0.0.1 访问时 SignalR 跨域被浏览器拦截，页面一直"连接中"，只能手动"立即读取"。已修复：① 后端启用 CORS（允许任意来源 + AllowCredentials）；② 总览页 SignalR 断线时每 5 秒轮询兜底；③ 测点管理页每 5 秒自动刷新列表。实测：127.0.0.1 跨域访问 SignalR 正常推送（2 秒一跳），测点页数值自动更新无需手动读取；顶部"模拟数据"徽标已改为动态（全部真实 PLC 数据时自动隐藏）。
